# Duels Reimagined diagnostics — initial BurstFX port

Status: implemented; actual WoW window/scan behavior unverified. User authorized copying BurstFX diagnostics functionality, removing BurstFX-specific checks, and adding launchers in Blizzard Settings landing and Addon Status.

Inspected original Handi’s BurstFX v0.1.0 Build 1004bugfix archive: Diagnostics/Engine.lua, DeepHealth.lua, DiagnosticsScanner.lua, DiagnosticsRegression.lua, IncidentRecorder.lua, Isolation.lua, LeakSentinel.lua, Performance.lua, Intelligence.lua, ReleaseGate.lua, ReportStore.lua, ReportWorkflow.lua, SafeRepair.lua, UI/CustomSettings.lua, and Core/HandisBurstFX.lua error capture sections. The old scanner/regression files alone are over 500 KB, tightly coupled to spec/overlay/CDM internals. Polestar Core/Compat.lua and mock testing patterns informed guarded reads and dependency isolation. No legacy class/spec checks are shipped.

This is an initial adapted port, not literal 100% feature parity. Provider engine, Health and complete pipeline, deep checks, exact existing simulated duel suite, state fingerprints, shared animation leak probe, per-check elapsed time, incident history, optional cached BugGrabber import, previous scan status, summary/advanced reports, three bounded saved reports (account Settings owner), select-to-copy and native shared button styles. Source and client verification are separate. No global error handler replacement; no guaranteed capture of uncaught errors without BugGrabber. Full leak instrumentation, historical comparison intelligence, standalone diagnostics storage addon, automatic async phase progress, raw SavedVariables schema audit, frame traversal and BurstFX-specific regression breadth remain unported. No fake PASS for those checks.

Run Health Check or Complete Check from either requested button or /duels diagnostics. Complete does pre-health, deep, Developer QA, isolation, animation leak comparison, final health, and explicit CI/multiplayer SKIP. Report text avoids roster names; incident text can contain names/paths, review before sharing. Save Report only on click; writes into DuelsReimaginedDB when WoW flushes SavedVariables on reload/logout. Clear Saved requires confirmation. Report storage is bounded to three 96 KiB texts. Scan does not change real duel records or settings. Existing real duel detector and simulation owner unchanged.

In-game test: open from each entry; Escape/close; run health/complete twice; verify 42 simulated cases and readable warnings/skips; select copy; save, reload and browse saved report; clear confirmation; run /duels detect and ensure live result unchanged; verify normal chat Enter, window navigation and resize; confirm no unrelated errors.

UI audit checks visible root/control dimensions, anchor presence, and readable atlas references, but not pixels or actual texture loading. No automated repair.

## Player-first diagnostics controls

Default window has Run Full Scan, Developer Tools, Copy Report and Close (plus existing header X). Run Full Scan calls the existing complete async pipeline, with full technical report automatically selected as the display mode. Copy Report selects the text for Ctrl+C; no claim that WoW can silently write the OS clipboard. Developer Tools starts collapsed every open and preserves quick health, summary/full report, performance, optional error capture, baseline, release gate, incidents, manual memory sample, saved reports and clearing. The report area grows when tools are collapsed. Close works while a batched scan is pending. No changes to scanner coverage, simulation, release semantics, memory refresh policy or live error-handler consent. A full scan includes every automatic check; explicit memory sampling, installing an error handler and saving/clearing a baseline remain deliberate developer actions. Polestar Theme/Widgets.lua W.Button primary/secondary hierarchy used as a design reference, with our own existing Style.Action controls.
