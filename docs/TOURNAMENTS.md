### Creator ownership and host migration requirement (user, 2026-11-25)
The creator remains the immutable owner of an event. Only that verified owner can authorize cancellation or supported edits; a temporary coordinator never inherits ownership, cancellation, or rule-edit permission. Proposed policy: lock competitive rules after first registration, and require explicit owner authorization for allowed edits before registration; no silent rule changes or incompatible re-advertisement. Participant copies replicate only the exact community and event. Coordinator authority is narrower: admit eligible players, record check-in, relay validated results and advance according to the approved rules. No proof of arbitrary match outcomes or owner privileges from a majority of copies. Stage 5A already refuses non-owner cancellation and publication, and treats published rules as immutable, but implements neither editing nor migration. Polestar Quests/Party.lua sender-to-roster validation (1247–1279), guarded send and retry handling (475–560), Core/Update.lua (340–385) checked again; Durotar Duelist TournamentCancel and ApplyLeave (972–1008) use admin authority. Keep sender binding and snapshots, not blanket admin authority.
Stage 5B must establish participant replication, bounded acknowledgments, event identity, validated sender-to-GUID binding, single commitment and durable recovery design. Stage 7 must implement coordinator succession with monotonic terms, mutually acknowledged checkpoint/version, fixed eligible voting set and deterministic candidate selection; no unilateral promotion merely because a timeout expired. Prevent two active coordinators, stale/forged revisions, owner cancellation spoof, unsafe membership changes, split partitions and late old-host packets. If authority cannot be established, pause mutations and progress without deleting or cancelling the event. If all peers are unavailable, no active coordination; resume only after verified recovery. Original owner returning reconciles before resuming any coordination. Creator disconnection is not cancellation. Include expiration/archive policy for abandoned events (not a participant cancellation). No external server or authentication guarantee; untrusted clients can lie, and actual game messaging/routing may prevent failover. No live public activation before actual multi-account failover and owner-only permission tests. The coordinator election, edit UI, actual persistence, and live networking are not in Stage 5A. Test and confirm the rule-lock policy with creator before enabling edits.
