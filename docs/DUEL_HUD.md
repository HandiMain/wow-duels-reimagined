# Duel HUD — independent companion

Status: IMPLEMENTED/UNTESTED foundation, with per-duel damage integration blocked. User approved the compact left-side concept direction and requested rank, movement, bounded resizing, default enabled, health and native duel actions. The widget uses the approved shared house palette, existing crest and rank assets rather than a new screenshot texture. Visual comparison and refinement are still required.

References: Polestar UI/Movers.lua (separate position/lock owner and combat-safe movement); EllesmereUI v9.8.9 archive EUI_UnitFrames_Text.lua (native SetMinMaxValues and SetValue for health), EUI_DamageMeters_Window.lua and EUI_DamageMeters_State.lua (native C_DamageMeter session read/reset), macro factory and secure action patterns considered. Five specialist duel ZIPs were listed but not accessible as raw bytes; no fresh inspection of them claimed. Native StartDuel/ForfeitDuel APIs used directly on explicit clicks rather than chat macros, subject to client verification. No third-party code copied.

One presentation owner UI/DuelHUD.lua subscribes to existing DuelDetection when visible. No replacement detector, automatic accept, forfeit, damage parser, rating calculation, network exchange or real match writes. UIParent independent 372x326 base layout; default on, unlocked, normalized position, 80–120% scale via Options / Interface / Minimap & Widget. /duels hud toggles visibility; /duels hud reset resets position/scale; /duels hud preview toggles isolated fictional visual values (no actions). Rank lookup uses the existing local peer read view on invalidation, not on health events. Unknown rank stays unknown; badge clicks only when a profile exists. Actual opponent must match a readable GUID, never silently replace with a new target. Health values delivered to native setters inside guarded calls; numeric percentage only if both values readable. No combat arithmetic on secrets. Local countdown estimate and since-acceptance timer; local observed outcome only, no automatic rating claim. Native damage display unavailable until exact per-duel isolation is established. A fresh private display session is initialized on each observed cycle; do not clear native damage history globally. No permanent idle OnUpdate. Existing competitive/War Games gates unchanged. No manual suite executed. GitHub CI may run automatically; pre-existing agreement suite failure is recorded, not fixed here.
