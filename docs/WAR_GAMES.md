# Retail War Games — approved design and test limits

This feature is Retail-only. The two Players layouts (setup and inside arena) and faction-neutral Host/Spectate layout were approved by the user; the 5v5 roster capacity is five fighters on each side. The host is not one of the fighters. Blizzard tournament match-mode is supported as an optional switch, OFF by default. Tournament brackets, /roll procedures, scoring and automatic results remain excluded.

Players: Detect the Blizzard party/raid through the shared Core/Group owner. Select 2v2, 3v3 or 5v5, an arena and one real Battle.net friend captain. The group leader may submit a StartWarGameByName request only with an exactly matching group size. The action never claims that anyone accepted or entered.

Host/Spectate: Select two DISTINCT real Battle.net friend captains, bracket and arena, then request StartSpectatorWarGame through Blizzard's API. We cannot reliably derive complete spectator team rosters; show selected captains and mark everyone else Awaiting player. Do not invent scores, classes, camera controls or match verification. The teams have no Horde/Alliance identity.

Arena: On Retail IsInInstance(... arena), hide match setup. Players see the Blizzard group and up to five arena1..arena5 opponent slots, only when Blizzard exposes nonsecret UnitName and UnitClass information. The interface does not interfere with ArenaCore or Blizzard arena frames. Leaving an arena restores setup selections.

Forever: Core/WarGames.lua and UI/WarGames.lua are excluded at load time by AllowLoadGameType standard, as verified in EllesmereUI and WarGameHelper. The War Games primary navigation plaque is gray, blocked from Search/workspace and click, but displays a helpful tooltip on hover. No Retail APIs run on Forever.

UI integrates with existing Window, Navigation, Theme, Search, Motion, Tooltips, Styles and Group. No added settings, SavedVariables, duplicate communication, polling or fake data. Battle.net friends and arena maps share the existing Options dropdown styling, hover and drag/wheel scrolling (one popup owner in Widgets). Their status dots are green/online or red/offline ONLY when Blizzard reports a boolean status; unavailable status is omitted. Team 1 and Team 2 captains are independent, and either can be cleared without changing the other. The Retail fallback lists 16 known arena maps; the optional Blizzard War Game type catalogue adds additional explicitly marked Arena entries when exposed. A reference entry does not guarantee live map availability. The War Games plaque is derived directly from the same Hall 256x128 sprite in DuelAtlas.png: only the baked swords and HALL text are replaced with the underlying red gradient, leaving the copper frame and laurels pixel-identical. War Games bakes original metallic crossed swords with a matched gold serif WAR GAMES title, at Hall's exact 205x84 geometry. The earlier mismatched brown concept crop was removed.

Sources inspected: Polestar Compat, WarGameHelper 1.2.6, ArenaLive Spectator, Wargames+, ArenaCore, EllesmereUI. The code is independently authored. API support and match behavior still require LIVE RETAIL MULTIPLAYER tests. Mocks only establish contract behavior.

Quick tests: Forever disabled hover; Retail open Players/Host, group count and leader restrictions, BNet picker including empty/friends and duplicate captains, map/bracket, disabled buttons, outside/inside arena transitions, minimum window size, tab/search/back/Enter/Escape, reload; friends verify real challenge, acceptance, spectator entry and five enemy slots.

## Visual regression correction (2026-11-23)

The first in-game Retail screenshot revealed a ghost Arena Match panel overlapping Your Team, two separate header dividers, clipped Retail Only copy behind Back, and mismatched warm-brown War Games artwork. Corrected by deleting the unused always-visible panel; removing the redundant title label and divider; reusing the original Hall skin; and giving each UI state independent, non-overlapping geometry. Host controls are four evenly sized columns. The Players setup card is above its team roster, with one card divider and status message. Panels are scrollable rather than drawn beyond the content area. All changes are visual only; no networking, Game API or match request changes.

The derived asset can be reproduced or verified with `python3 tools/community/generate_wargames_plate.py [--check]`. Only the already-owned Hall atlas is used. This avoids independent painted frames that drift away from the main addon design.

## Picker / logo correction (2026-11-23)

The original War Games baked title touched the lower inner ornament: its serif mask is now centered and scaled to fit safely inside the plaque. Arena and Battle.net friend pickers reuse exactly the Options dropdown controls, popup art, hover, scrolling and close behavior; Previous/Next paging has been removed. Fixed the Lua `and/or` fallback which accidentally displayed Team 1's captain in Team 2 when the second slot was unselected. Added negative tests covering one-friend and clearing scenarios. These changes do not validate War Game multiplayer behavior.

## Scrollbar and War Games identity refinement (2026-11-23)

The War Games ScrollFrame previously painted child cards using almost the entire viewport width (minus 5px), overlapping the shared 12px scrollbar and its hit target on initial show; a window resize masked the problem. The UI now reserves a fixed 22px gutter from the anchored main-content width, recalculates all team panel widths with the same usable-canvas width, listens for size changes on both viewport and root, and performs one deferred first-show reflow (no polling). This applies to Players and Host, both lobby and in-arena views. The button uses an original simple silver-and-gold arena shield with a central star, replacing the over-detailed coliseum gate. The compact crest is baked into the Hall-derived plaque while preserving the frame, laurels, title and interaction effects. The generator reads `tools/community/artwork/WarGamesArenaCrest.png`; only the final plaque texture is loaded in WoW.

## Compact emblem and stable scroll gutter

The simplified War Games shield is a high-contrast faction-neutral symbol, not Hall's crossed swords or a detailed building. Only the final Hall-derived plaque loads in WoW, with one lightweight indexed PNG as reproducible source. The former gate source is deleted. Both Players and Host team cards calculate against the usable width (viewport minus the 22px scrollbar gutter), while the scroll child itself spans the viewport. The VS ornament uses the same usable width. This prevents scroll-child sizing from pushing the right border behind the scrollbar on initial show or resize. Actual WoW layout and multiplayer entry remain pending final tests.

## Tournament Rules option (2026-11-23)

Retail Players and Host / Spectate each have an independent **Tournament Rules** toggle, OFF by default. It reuses the existing compact `Widgets.ToggleRow`, click/hover motion and tooltip. Both toggles are listed in Search and share the action row with Send Challenge / Request Spectator Match. The card sizes and scroll gutter are unchanged.

Tournament Rules is a session-only **match option**, not a global Options preference; it does not enter SavedVariables and resets to OFF on reload. The original player request ends in `0` and spectator request passes `false` when OFF; when ON they send `1` and `true` respectively. Current arena/team/captain checks remain untouched. No result, opponent acceptance or spectator entry is invented.

References: Polestar's existing toggle and disabled-state UX, Duels Options' own `ToggleRow`, the Retail Blizzard spectator slash command (`ValueToBoolean(isTournamentMode)`), and the Warcraft Wiki `/wg ... [tournamentrules]` parameter. These support API payloads but not live match success.

Live QA: On Retail check both independent toggles, tooltips, Search, minimum-size layout and default-off reload; send ON/OFF challenge and spectator requests with consenting teams and verify Blizzard's real outcome. On Forever the War Games page stays unavailable. Multiplayer results remain **NOT VERIFIED**.

## Selected hybrid visual arena picker (2026-11-23)

**Concept approved:** the user selected the centered **CHOOSE ARENA** 2-column gallery concept with a small preview and **Change Arena** control inside the existing Players and Host / Spectate match setup panels. The prior simple arena dropdown is replaced; Battle.net captains continue to use the shared Options-style dropdown. The existing Coliseum plaque, footer/header, team rosters, Tournament Rules, and all request logic remain unchanged.

**Implementation: UI/WarGamesArenaPicker.lua (Retail only).** Both pages use one compact preview button and one modal with a scrollable 2-column card grid, title, search field, **All Arenas / ★ Favorites** filters, visible hover/click, selected gold outline/check, close X, Cancel, and Select Arena. A pending selection is not applied to the game request owner until Select Arena is clicked; Cancel/Escape/outside click leaves the existing arena unchanged. Mouse wheel and the addon-standard scrollbar are supported. Opening the picker closes any captain popup. Changing pages, hiding the addon, or entering an arena closes the modal. The visible match setup card grows just enough to fit the 72px selected arena preview without overlapping the original tournament toggle and request action; its team panels remain in the same relative order and retain the scrollbar's 22px reserved gutter. Resize calculations are event-driven, no permanent polling.

**Genuine Blizzard game art ONLY.** The popup attempts native Retail arena-specific loading screen textures documented by the Details! arena info table: Nagrand Arena (`LoadScreenNagrandArenaBattlegrounds`), Blade's Edge (`LoadScreenBladesEdgeArena`), Ruins of Lordaeron (`LoadScreenRuinsofLordaeronBattlegrounds`), Dalaran Sewers (`LoadScreenDalaranSewersArena`), Tol'viron (`LoadScreenTolvirArena`), Tiger's Peak (`LoadingScreen_Shadowpan_bg`), Ashamane's Fall (`LoadingScreen_ArenaValSharah_wide`), and Black Rook Hold (`LoadingScreen_BlackrookHoldArena_wide`). The four legacy arena LFG icons are documented in Blizzard's older `PVPFrame.lua`, as reliable secondary candidates for their corresponding arenas. Each path is checked using Retail `GetFileIDFromPath` and rendered by the **client's own texture fileID** only when it exists; no unverified map-specific file names, external URLs, copied media, or AI-generated images are shipped. For all other arenas—including newly reported Retail client arena names—or a loading texture absent on the user's client, the correct arena remains selectable with a plainly labeled **PREVIEW UNAVAILABLE** thumbnail. This avoids displaying a fake or incorrect arena scene. Client validation of these texture paths remains **IN-GAME UNTESTED**.

**Ownership and persistence:** Core/WarGames.lua remains the only game request/selection owner; its arena catalogue is unchanged. `Core/Settings.lua` owns the sole account-wide bounded, validated `warGamesArenaFavorites` list (maximum 32 names). No second storage owner. The modal reuses shared Style, Widgets scrollbar, Motion and Tooltips. The optional favorite star on each card adds/removes that arena from Favorites. Favorite filter and pending choice are temporary. No new communication, match sync, ranking, gameplay event, OnUpdate or auto-selection behavior.

**Reference provenance:** Polestar's picture-card picker, preview-first selection and state-aware controls; Blizzard's original arena icon mapping (`Interface/FrameXML/PVPFrame.lua`); Details! boot.lua documented arena loading screen art; BurstFX's now-retired graphical gallery provided a warning against letting a picker dominate the main page. Only a lightweight modal is shown on demand. No reference Lua is copied.

**In-game test (Retail):** Open Players, inspect the current map preview, Change Arena, search, scroll, favorite/unfavorite, switch Favorites/All, click a different thumbnail, Cancel (old map remains), reopen and Select (new map appears). Repeat in Host, resize the addon to default/minimum and taller sizes, press Escape, click outside, switch tabs, and close the addon mid-picker. Verify full image rendering for all 8 documented maps, and correct **PREVIEW UNAVAILABLE** for maps with no validated native client art. Test an empty favorite filter, a no-match search, and an arena with a long name. Verify original captain chooser and Tournament Rules and send-button preflight remain operational. Forever: the entire War Games UI and gallery remain unavailable. Authentic client image resolution, interaction feel, and live multiplayer requests remain unverified until the player tests in WoW.

## Arena browser visual-fidelity repair (2026-11-23)

Handi's first Retail screenshot of the visual picker showed a tan/brown modal, an opaque gold Nagrand card, darkened/cropped arena images, missing-font boxes for favorites/checkmarks, and a picker floating too high above the footer. These are **visual bugs**, not permission to redesign gameplay. The exact root cause is that the shared `Style.Fill` helper **automatically creates a SetAllPoints anchor**. The new picker subsequently added edge-only `SetPoint` anchors to three of these full-parent fills without first calling `ClearAllPoints`: the modal divider flooded the modal with gold, the card footer bar covered the entire arena image, and each gold selected-card rim covered the entire picture. All three are now explicitly cleared before their thin rectangle anchors are applied. Tests assert this regression boundary.

The one existing modal remains owned by `UI/WarGamesArenaPicker.lua`, but now reuses the approved `shellCopper` 9-sliced frame art over the dark `C.nav` house panel, displays our existing crossed-swords Hall icon beside CHOOSE ARENA, and anchors near the bottom of Window.content as in the chosen concept. Search, active filter choices, two-column image cards, the right-side scrollbar gutter, and bronze/gold Select Arena vs red Cancel action were aligned. To avoid black rectangles caused by missing Unicode glyphs in WoW and optional Ellesmere fonts, the three purpose-made 32px icon glyphs (outlined gold favorite, filled gold favorite, gold check) are packed in a tiny 128x32 TGA; this is decorative only, with native WoW buttons/hover/input retained. No new custom font is bundled.

**Result status: IMPLEMENTED / UNTESTED IN GAME.** All real arena client-loading-screen source mappings remain unchanged. The previously gold-blocked Nagrand artwork should now be visible, but actual in-game fidelity and unverified/historical art path resolution must be checked by the user. Prior matchmaking, selections, live arena behaviors, networking, SavedVariables ownership, team layout, player/chat focus, and accessibility are not changed by this visual-only repair.

## Quiet gallery and missing-image artwork (2026-11-23)

The War Games Arena Selector no longer creates tooltips for the collapsed preview, individual arena cards, favorite stars or any popup action buttons. The shared `Style.Action` accepts a **scoped** `palette.tooltip=false` opt-out used only by this popup; existing Options, Hall, Patch Notes and other tooltips keep their current behavior. Hiding existing tooltips when the picker opens also prevents a leftover hover panel.

**Artwork preference:** Use native Blizzard client loading screens and original arena icons first, if that exact map's texture path resolves. Otherwise, for the following nine known maps use a bundled illustration drawn from researched in-game screenshot references: Nagrand Arena, Cage of Carnage, Empyrean Domain, Enigma Crucible, Hook Point, Maldraxxus Coliseum, Mugambala, Nokhudon Proving Grounds and The Robodrome. These images are **AI-generated recreations** (NOT authentic screenshots and NOT official Blizzard artwork). All nine correspond to specific distinct coordinates in `Media/Arenas/WarGamesArenaFallback.png`, a 1024x512 atlas of 256x128 thumbnails. Unfamiliar client-discovered arenas still show PREVIEW UNAVAILABLE rather than an illustration incorrectly labeled as another arena. No gameplay, tournament, roster, or networking logic is changed.

**Automated checks:** PNG metadata and SHA256, all nine atlas mappings, native-art priority, empty/unknown fallback, absence of tooltip bindings in the gallery, and the scoped shared Action tooltip opt-out. **Live test:** check all 16 built-in arenas, especially Nagrand and the eight newer maps, both page modes, no hover popups, and confirm native/art recreation thumbnails with a screenshot. Distinguish actual source texture IDs from generated illustration; an image is not evidence that an arena is currently queueable. **Status:** IMPLEMENTED/UNTESTED in WoW.

## Arena picker buttons use approved shared chrome — 2026-11-23

**Appearance approved:** the user selected the concept with a miniature red/gold header X, dark forged filters, gold active filter, red Cancel and gold Select Arena. This was a visual-only follow-up to the functioning arena gallery; no arena selection, generated-art fallback, favorites, scroll, or Warcraft API behavior changed.

The picker formerly passed a locally specified fill/edge palette to `Style.Action`, making generic rounded capsules rather than our approved copper/gold footer artwork. The fix adds an **opt-in** `palette.plate` to that existing shared button constructor; callers without a `plate` continue to use their previous skin and input behavior. All Arenas / Favorites switch the same reusable plate between `dark` and `gold` on selection, while Cancel uses `hall` (identical red forged art to the main footer Close) and Select Arena uses `gold`. An opaque rectangular selected overlay was removed so the underlying button details are visible.

The popup X is created with `ns.Header.CreateCloseButton(parent)`, which calls the same existing `HeaderButton("Close")` factory that draws our main header's Close icon, native pressed offset, bronze/red plate, click feedback and hover glow. Its parent is the gallery popup and its tooltip is suppressed; the main header X remains unchanged. No duplicate action engine, extra permanent event handler, new media or SavedVariables. Layout and all match functionality remain unchanged.

**Evidence:** static source/regression assertions, Lua syntax and contract tests in CI when run. **IN-GAME TEST REQUIRED:** open popup, inspect X icon size/centering, red Cancel art, gold Select, dark idle filters and gold active filter; hover/click each and verify feedback, tooltips remain hidden, cancellation does not change selected arena, and resizing leaves layout intact. Automated passes do not prove live look.
